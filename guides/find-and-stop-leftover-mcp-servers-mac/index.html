How to find and stop leftover MCP servers on a Mac

The short answer

  1. List processes with their parent and age, and keep the ones whose command line mentions an MCP server.
  2. A leftover has parent 1 and no agent session open in its project.
  3. Stop each one with plain kill <pid>, wait a few seconds and check again. Reach for kill -9 last.

Everything below uses tools that ship with macOS. It works without Overstay.

Command lines can contain API keys and other secrets that were passed as arguments. Read the output before you paste it into a public issue or chat, and remove anything private.

1. List the candidates

ps -axww -o pid,ppid,etime,rss,command | grep -E 'mcp|modelcontextprotocol' | grep -v grep

The columns are the process id (pid), its parent (ppid), how long it has been running (etime), its resident memory in kilobytes (rss) and the full command. -ww stops the command being cut at the width of the window. Run man ps for the rest.

This lists servers that belong to agents you are using right now as well as leftovers. The next step separates them.

2. Keep the orphans

ps -axww -o pid,ppid,etime,rss,command | awk '$2 == 1 && /mcp|modelcontextprotocol/'

A parent id of 1 means the process was adopted by launchd: whatever started it has exited. That is the mark of a leftover, but not proof, because things you start on purpose with nohup or as a login item look the same. This filter also misses servers whose command line has no "mcp" in it, so read the full list once.

3. Find out which project it belongs to

lsof -a -d cwd -p 12345

Replace 12345 with the pid. The NAME column is the folder the process was started in. If an agent session is open in that folder right now, leave its servers alone: they may be in use.

If the command starts with docker

A server launched with docker run -i is a docker client process plus a container. Stopping the client does not necessarily stop the container. List containers with docker ps and stop one with docker stop <container> (Docker's reference). Check that it is not a container you started yourself first.

4. Stop one, politely

kill 12345
sleep 5
ps -p 12345 -o pid,ppid,etime,command

kill with no option sends SIGTERM, the request to quit. Most servers handle it and exit. If ps prints nothing, it is gone. If it is still there after a few seconds, look at it again before you escalate.

Do one at a time. Some servers have child processes of their own; stopping a parent can leave its children behind with parent 1, so list again afterwards and stop those the same way.

As a last resort for a process that ignores SIGTERM:

kill -9 12345

SIGKILL cannot be caught. The process gets no chance to close files, remove lock files or finish writing, so use it only when you know nothing there matters.

What not to run

  • pkill -f mcp, pkill node, killall node. These match by name, so they also stop the dev servers, build tools and editor helpers you are using, and the servers of sessions that are still working.
  • kill -9 as the first move. It skips every chance at a clean exit.
  • kill 0, kill -9 -1 or a negative pid. They signal a whole process group, or every process you are allowed to signal, not one.
  • Anything run with sudo on a process you did not start. System and other users' processes are not leftovers.

Zombies cannot be stopped

If ps shows the state Z (add stat to the -o list), the process has already exited and is waiting for its parent to collect its exit status. It holds almost nothing and kill does nothing to it. Only the parent clears it, usually when the parent exits. Why that happens.

Keeping them from piling up

  • Exit the agent normally rather than closing the terminal window or force-quitting.
  • Remove servers you do not use from the agent's configuration.
  • Keep the agent and its servers up to date, and check the agent's issue tracker for your version.
