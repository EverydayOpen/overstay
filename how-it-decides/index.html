03 · How it decides

How Overstay decides what is a leftover

A process is listed only when every rule holds. Anything that only half fits is shown as a Maybe, with the reason, and is never part of a bulk stop.

These rules describe the code in the repository. Nothing has run on a real Mac yet, so the patterns are checked against real process output only after testers have tried it. The list below will change.

The short version

  1. It is your process, and not on the protected list.
  2. It matches a known agent tool: a tool server, an agent worker or an automation browser.
  3. Its parent is gone.
  4. No live agent session is using the same project.
  5. Its project is known, it does not listen on a network port, and nothing still writes to its input.
  6. It started at least ten minutes ago.

All six: a Leftover, pre-selected. The matching and parent rules but not the rest, or only a generic match: a Maybe.

Before any rule: what can never be selected

Overstay first asks whether a process is allowed to be touched at all. These are protected. They are shown with the reason where relevant and can never be selected, planned or stopped. You can add to the list in Preferences; nothing can remove from it.

launchd, kernel_task, WindowServer, loginwindow, Finder, Dock
anything under /System, /usr/libexec, /usr/sbin, /sbin, /Library/Apple
anything inside an app bundle (except a recognised automation browser)
Terminal, iTerm, Ghostty, WezTerm, kitty, Alacritty
tmux, screen, zellij
ssh, sshd, ssh-agent, gpg-agent
Docker, Colima, Lima, OrbStack and VM helpers
databases (postgres, mysqld, mongod, redis-server, ...)
language servers (sourcekit-lsp, clangd, gopls, rust-analyzer, ...)
a process in a terminal session whose leader is still alive
an agent session or editor host itself (the tool you are working in: Cursor, Zed, Windsurf, VS Code, ...)
Overstay itself, and every program that started it
another user's processes

The rules

  1. It matches a known agent tool

    A signature in a plain list in the source, one line per tool. Tool servers (@modelcontextprotocol/server-*, names starting mcp-server- or ending -mcp, Playwright and DevTools servers), helpers of agent apps, and automation browsers. For tool servers the arguments are searched only when the program is a launcher such as node, npx, uvx or python, so a text editor with "mcp" in a file name never matches.

    signature

  2. Its parent is gone

    Its parent is launchd, or everything above it up to a launchd child is itself a matching, unprotected process of yours (the tree an agent left behind). A parent of 1 alone means nothing, since many apps have it.

    ppid 1

  3. No live session owns it

    If a running agent shares its project, it may be in use and becomes a Maybe. Project means its working folder, or the nearest parent folder with a .git entry, found by looking only at whether the entry exists, never at its contents.

    no session

  4. Nothing points to it being on purpose

    Its project is known, so a live session can be ruled out. It does not listen on a network port (--port, --host, --sse, a non-stdio --transport or a --listen address), which a server you started yourself might. Nothing else still holds the other end of its input pipe. Any of these makes it a Maybe.

    on purpose?

  5. It has been there a while

    Started at least ten minutes ago. You can raise the gate in Preferences; it never drops below one minute.

    ≥ 10 min

Browsers are the strictest. Your everyday Chrome never matches: an automation browser needs a marker such as Chrome for Testing with --headless or --remote-debugging-pipe, a Playwright or Puppeteer browser, or chrome-headless-shell.

The tiers, with an example each

Every row in the app carries a one-sentence reason in these words. The examples use the sample data.

Agent tool servers · ~/dev/fooLeftover

Parent is gone. Looks like an MCP server. No live session in foo.

Agent tool servers · ~/dev/barMaybe

Parent is gone. Looks like an MCP server. A live session is using bar, so it may still be needed.

MCP server · ~/dev/bazMaybe

Parent is gone. Looks like an MCP server. Started 4 min ago, under the 10 min age gate.

Agent tool servers · ~/dev/apiMaybe

Parent is gone. Looks like an MCP server. It listens on the network, so it may be a server you started on purpose.

Dev server · ~/dev/quxMaybe

Parent is gone. Matches a generic pattern, so Overstay is not sure.

Not listedIgnored

Not a leftover: its parent is still running. Ignored processes are never shown.

Not selectableProtected

Protected: inside an app bundle.

An unknown project (it could not be read, so a live session cannot be ruled out) and something still holding the other end of its input pipe also make a Maybe. Dev servers (Vite, webpack, Next.js, esbuild) match only generically, so they can be a Maybe at best. A Maybe is never pre-selected and never part of a bulk stop. You stop it one at a time, and one that started under 24 hours ago asks for one more confirmation.

It got one wrong

A detection rule that lists something you still need is a bug we want to hear about. Open the form, describe what the process was and why you needed it, and never paste secrets.
