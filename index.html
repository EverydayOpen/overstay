How it decides.

A process is listed as a leftover only when all of these hold. A name alone is never enough.

  1. It matches a known agent tool

    Tool servers, agent workers and automation browsers, from a list of signatures. Your everyday Chrome is never on it.

    signature

  2. Its parent is gone

    A process whose parent exited is adopted by launchd. Many ordinary apps are too, so this counts only together with a match.

    ppid 1

  3. No live session owns it

    If a running agent still works in the same project, the process may be in use. Then it is not a leftover.

    no session

  4. It has been there a while

    It started at least ten minutes ago.

    ≥ 10 min

Anything that only half fits is a Maybe: shown, never pre-selected, never in a bulk stop. An unknown project, listening on a network port, or something still writing to its input also make it a Maybe. Your own processes only, and never anything on the protected list. Read the rules in full.

What it reads. What it never does.

It touches processes, never files. The rules are written down, and a check in CI fails the build when code breaks one of the mechanical ones.

Reads

  • The process table

    Process id, parent, start time, owner and program path.

  • Memory

    The memory footprint of each process.

  • Your own processes

    Their working folder and arguments, read in memory to spot agent tools, with anything that looks like a secret scrubbed before it is shown.

  • A few variable names

    Whether certain well-known environment variables are set. Never their values.

Never

  • Ask for permissions or a password

    No Full Disk Access, Accessibility, Automation or root helper.

  • Connect to a network

    No telemetry, no account, no update check.

  • Read, move, edit or delete a file

    It writes only its activity log, a share card you save yourself, and its preferences (kept by macOS in the app's defaults).

  • Touch what is not yours

    No other user's or system processes, no terminal or editor with a live session, no process group.

  • Promise an undo

    A stopped process is gone. Overstay says "held", never "freed".

Every rule, and what the log holds.

Nothing leaves your Mac.

Overstay has no server to talk to. This website has no analytics, no cookies and no third-party requests.

  • No network

    No telemetry, no account, no update check. A check in CI fails the build if a networking API appears.

  • No permissions

    Nothing to grant in System Settings, and no elevated rights.

  • A local log

    Every stop is appended to a file only you can read: tool, program name, process id, project folder name, result. No arguments, no environment.

  • Names off by default

    The share card shows counts and sizes. Project names appear only if you tick the box.

02 · Questions

Before you try it.

Short answers. The long ones are in the guides and on the safety page.

Will this break my build?

Overstay lists only processes whose parent is gone and that no live agent session is using, and it never pre-selects a Maybe. Even so, a stopped process cannot be brought back, so anything unsaved inside it is lost. The confirm step lists exactly what will stop before you agree.

Why not just run pkill node?

pkill matches by name. It also stops the dev server you meant to keep and the helpers of an agent session that is still working. Overstay checks which tool started a process and whether anything still owns it, then checks each one again right before asking it to stop.

What is a Maybe?

A process that only half fits: it matches a rule, but a live session might still use it, it is young, its project is unknown, it listens on a network port, something is still writing to its input, or the match is generic. Maybes are shown with the reason, never pre-selected and never part of a bulk stop. Anything under 24 hours old asks for one more confirmation.

Which tools does it recognise?

Tool servers (MCP and similar), automation browsers and a few agent helpers such as the ones Codex starts. Which tool started a group is a best guess until testers confirm it on real Macs. Cursor, Zed, Windsurf, VS Code and the agent sessions themselves are recognised only so they are protected and never listed. The names are there only to say what Overstay looks for. Overstay is not affiliated with or endorsed by any of them, and ships no vendor logos. The list is plain data in the source, one line per tool.

Does it work on my Mac?

It targets macOS 13 or later, Apple silicon and Intel. Nothing has run on a real Mac yet; the tester beta is how we find out, and the changelog will say what was tried.

Is it really free?

Yes. MIT licence, no account, no trial, no paid tier. The source is on GitHub.

Why is the app unsigned?

Until there is a Developer ID, public builds are unsigned betas, so macOS asks for one extra step the first time you open it. The download page shows it, with a checksum to compare.
