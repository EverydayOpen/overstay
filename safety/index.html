04 · Safety and privacy

What Overstay reads, and what it never does

Overstay stops processes, so a bug could stop the wrong one. These are the rules it is built under. Most of the mechanical ones are checked by scripts that run in CI and fail the build when code breaks them.

Status on 2 October 2026: the detection and planning logic has automated tests. The macOS parts have not been compiled in CI or run on a real Mac yet, so read everything here as the design, not as proof that it works. The changelog will say what testers have tried.

The short version

  • Processes only. It never deletes, moves, edits or reads the contents of a file.
  • Your own processes only, and never anything on the protected list.
  • Polite first. The gentle signal, children before parents, a five second wait, and a stronger one only when you click for it, one group at a time.
  • Nothing leaves your Mac. No network, no account, no telemetry, no permissions.
  • No undo. A stopped process is gone, and Overstay says so before you confirm.

What it reads

  • The process table

    For every process: id, parent, start time, owner, program path and whether it is a zombie. Only your own processes are ever considered; others are read only to follow a chain of parents.

  • Memory

    The memory footprint of each listed process, shown as "held". It is not a promise of how much memory is free afterwards.

  • Arguments and working folder

    Of all your own processes, because spotting an agent tool needs them. Arguments are read into memory, scrubbed (anything that looks like a key, token, password or credential is replaced), clipped, and shown on your screen. The one exception is Help > Copy Diagnostics, which copies a scrubbed summary to your clipboard only when you choose it; read it before posting.

  • Whether a project is a project

    It looks for a .git entry by asking whether it exists, nothing more. It does not open it.

  • A few variable names

    Whether two well-known variable names are set in a process's environment. Overstay never keeps, shows, logs or copies a value, or the name of any other variable.

What it never does

  • Ask for permissions

    No Full Disk Access, Accessibility, Automation or Screen Recording, no login item and no root helper. It is not sandboxed, because a sandboxed app cannot see other processes, and it needs no entitlement. It sends no notifications.

  • Use the network

    No telemetry, no account, no update check. A script rejects the common networking APIs in CI.

  • Change a file

    The only things it writes are its activity log, a share-card image you save yourself, and its preferences (kept by macOS in the app's defaults).

  • Touch what is not yours

    Not another user's or the system's processes, not your terminal, shell or editor, not a process group, never process 1 or lower, never itself.

  • Run a shell or another program

    No ps, pkill, lsof, no shell, no child process. It reads the process table through the system's own calls.

  • Promise what it cannot

    No undo, no "freed memory", no "session ended". A row says "started 3 days ago", because Overstay cannot know when a session ended.

How a stop works

  1. You confirm exactly what will stop

    The confirm step lists every process in plain words. The default selection is leftovers only; Maybes are never in a bulk action.

    confirm

  2. It checks each process again, right before acting

    Same process id, same start time, same program, same owner, still a leftover. If anything changed (a reused process id, say) it is left alone and logged as changed since the scan.

    re-verify

  3. The gentle signal, children first

    The deepest processes first, then their parents.

    SIGTERM

  4. It waits, then tells you what is left

    Up to five seconds, returning early when everything has exited. Survivors are listed.

    5 s

  5. The stronger signal is a separate click

    Only for one group, only after its own confirmation, never automatic and never in a loop.

    SIGKILL

All signalling lives in one source file, Signal.swift, and CI fails if a signal call appears anywhere else. It only ever signals one positive process id greater than 1.

The activity log

Every target of every stop, including skipped and failed ones, is appended to a file in ~/Library/Application Support/Overstay/, readable only by you. A line holds the time, the tool, the program name, the process id, the project folder name, the memory, the result and the one-sentence reason. It holds no arguments, no environment and no full paths. A line is written before each signal is sent; if it cannot be written, that signal is not sent.

Privacy

The app

It collects nothing and sends nothing, because it makes no network connection at all. Scrubbed arguments are shown only on your screen; the one exception is Help > Copy Diagnostics, which copies a scrubbed summary to your clipboard only when you choose it. Read it before posting. The share card contains counts, sizes and tool names; folder names appear only if you tick the box, and nothing is shared unless you copy or save the card yourself.

This website

It sets no cookies, runs no analytics, loads no third-party scripts, fonts or images, and makes no request beyond its own files. A strict content policy enforces that in your browser. The site is hosted on GitHub Pages, which keeps its own server logs under GitHub's privacy statement; we do not receive them.

Why you can check all of this

  • It is MIT licensed and has no third-party dependencies in version 1.
  • Safety rules are written down in the repository and the mechanical ones are scripts you can run yourself.
  • Builds come only from GitHub Releases, with a checksum in the notes.

To report a vulnerability, or a way to make Overstay stop something it should not, see the security policy.
